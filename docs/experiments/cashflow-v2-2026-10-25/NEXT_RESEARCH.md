# 두 후보 기각 후 다음 연구 선택

**다음 한 가지는 ‘실제 바이낸스 선물시장의 펀딩·미결제약정·시장구조를 이용한 4시간봉 연구’로 선정한다.** 가격 봉 주기만 바꾸는 방향보다 새로운 정보가 추가되고, 시점별 펀더멘털 사건 패널보다 짧은 비용으로 가설을 기각할 가능성을 평가하기 쉽기 때문이다. 이는 연구 우선순위 판단이며 해당 전략의 양수 기대수익이나 성공확률이 검증됐다는 뜻은 아니다. 이번 PR에서는 이 선물 전략을 구현·백테스트하거나 레버리지를 적용하지 않는다.

## 같은 기준으로 비교

아래 개발비용은 기존 인프라를 재사용할 때의 엔지니어링 계획 추정(1인 작업일)이다. 외부 견적이나 확정 일정이 아니며, 데이터 구매·서비스 운영비는 포함하지 않는다. 세 방향 모두 검증된 순기대수익률과 수치화할 수 있는 미래 성공확률은 현재 없다.

| 방향 | 기대수익 판단 | 성공 가능성에 대한 현재 근거 | 개발비용 추정 | 데이터 확보 가능성 | 위험 대비 연구 보상 |
|---|---|---|---|---|---|
| 1. 가격 중심 선물 4시간봉 스윙 | 기회·매도 방향이 늘 수 있으나 회전 비용·펀딩이 상쇄할 수 있음. 수익률 추정 불가 | 이번 실패와 다른 주기라는 사실만으로 새 우위를 기대하기 어려움. 가격만의 후속 우선도는 낮음 | 약 4~8일, 선물 마진·체결 검증에 추가 시간 가능 | 공식 4h 가격 이력은 공개 자료로 조사 가능. 실제 선물 종목·상장/폐지·마크가격 이력도 필요 | 구현은 빠르지만 같은 가격 가설을 반복할 위험이 큼 |
| **2. 펀딩·OI·시장구조 + 4시간봉** | 포지션 혼잡·자금 조달·수급 불균형이 추가 정보일 수 있음. 비용 후 양수 여부는 미확인 | 새 정보에 대한 명확한 귀무가설과 가격만의 대조군을 만들 수 있음. 세 방향 중 연구 효율 우선 | 약 10~20일, OI 출판시각·결측 검증 실패 시 중단 | 펀딩 이력 API 존재. OI REST는 최근 1개월만 제공하므로 장기 원시 아카이브와 실제 가용시각의 별도 확인이 관건 | 데이터 감사가 선행되면 정보의 추가 가치를 빠르게 검증 가능. 청산·펀딩·거래소 위험은 높아짐 |
| 3. 사용량·공급·가치귀속·자본 유입 재평가 | 사업 성장·희석 변화와 토큰 가격 재평가의 연결을 시험할 수 있으나, 프로토콜 성장과 토큰 수익은 다를 수 있음. 수익률 추정 불가 | 경제적 설명은 직접적이지만 수치 수정·사후 선택·희소 사건 때문에 현재 성공확률을 매길 수 없음 | 약 25~50일 이상 + 지속 수집·사건 검수, 데이터 권리·서비스 비용 별도 | 일부 사용량·수수료·매출 이력은 공개. 과거 당시의 토큰 권리·공급·발표·수집시각까지 완전한 패널은 별도 구축 필요 | 장기 연구 가치는 크지만 이번 자본·검증 속도 목표에서는 가장 비쌈 |

[Binance 공식 공개 데이터 문서](https://github.com/binance/binance-public-data)는 현물·선물 kline과 4h 주기를 설명한다. 다만 이 문서 자체가 실제 장기 OI 커버리지를 보증하지는 않는다. [Binance 선물 시장 API 문서](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)는 펀딩 이력과 OI 이력 API를 제공하고 OI 통계의 최근 1개월 제한을 명시한다.

펀더멘털 방향에서는 TVL·사용자가 지불한 수수료·프로토콜 매출·토큰 보유자 귀속 수익을 구분해야 한다. [DefiLlama 정의](https://docs.llama.fi/analysts/data-definitions)와 [공식 API 명세](https://github.com/DefiLlama/api-docs/blob/main/llms-free.txt)에 관련 구분·이력 조회가 있다. [갱신 주기 설명](https://docs.llama.fi/faqs/frequently-asked-questions)에 따르면 지표의 갱신 주기도 다르다. 현재 API가 반환하는 수정된 과거 값이 당시 투자자가 사용할 수 있던 값과 같다는 보장은 여기서 확인되지 않았다. 따라서 발표·수집 시점 검증이 필요하다는 판단은 연구상 추론이다.

## 선정한 연구의 첫 종료 조건

1. **우선 데이터 감사**: 실제 선물 상장·폐지·계약 동일성, 4h 체결 가격, 마크/지수 가격, 실제 펀딩 시각·율, OI 관측 시각·가용 시각을 원시 출처·해시와 함께 확보한다. REST의 최근 OI를 과거 전체로 소급하거나 현재 생존 종목만 남기지 않는다. 장기 OI 공개 시점 또는 원시 커버리지를 확인하지 못하면 해당 역사 백테스트를 NEEDS_MORE_EVIDENCE로 끝내고 수익성을 주장하지 않는다.
2. **가설 하나만 사전등록**: 가격만의 고정 4h 정책에 비해 펀딩·OI·체결 수급 정보가 비용 후 기대값을 개선하는지 시험한다. 예를 들어 ‘과도한 펀딩과 OI 증가 뒤 혼잡 해소’를 하나의 가설로 정하고, 실제 사용할 정의·지연·방향·청산·통계·기준을 데이터 성과 열람 전에 고정한다. 이 문서의 예시는 실행 가능한 고정 전략이나 이미 선택한 파라미터가 아니다.
3. **동일 시각·동일 위험 대조군**: 가격만의 대조군과 무작위 대조군, 연속 계좌와 연도·시기별 계좌를 사용한다. 펀딩은 실제 기록 시각별로 부과하고 일률적인 8시간 상수를 가정하지 않는다. OI의 봉 마감·출판·수집 시각과 신호 지연을 구분한다.
4. **먼저 레버리지 없는 명목노출 검증**: 현물 수익에 배수를 곱하지 않는다. 실제 선물의 마진·마크가격·펀딩·강제청산 및 동시 위험을 별도 엔진에서 검증하고, 기준 통과 전 레버리지 확대를 금지한다. 기존 브로커의 상시 총위험 증가 문제도 새로운 프로토콜에서 정의하고 확인한다.
5. **돈을 투입하기 전 폐기 기준**: 스트레스 PF > 1.3, 전체/도전 표본 200/50, MDD 15%, 시기별 안정성·블록 재표본·대조군 기준과 경제적 월 성장 문턱을 최소한 유지한다. 하나라도 실패하면 그 버전을 보존하고 기각한다. 통과해도 새로 시작하는 최소 90일의 주문 없는 전방 검증이 필요하다.

실제 선물 계약의 자료가 확보되지 않은 상태에서 예상 월수익이나 레버리지 배수를 정하지 않는다. 자본 2,000만 원에서 월 500만~1,000만 원이라는 목표는 계속 성과 목표로 남긴다.

## 펀더멘털 후속 연구를 시작할 때의 최소 조건

3번을 뒤에 진행한다면 원래 설계의 **최소 200개 시점 기록 사건**을 유지한다. 사건시각·공개시각·수집시각·효력시각, 토큰 동일성, 사용량/수익 변화, 토큰 가치귀속, 공급/언락 변화, 원문 URL과 원시 스냅샷이 필요하다. 가격 상승 뒤 현재 자료를 붙이는 사후 서사는 사건 패널로 인정하지 않는다. 사용량과 가격의 동시 상승만으로 원인·저평가·자본 유입을 확정하지 않는다.
