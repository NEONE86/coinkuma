# ONE Flow Scalper v1 — 실시간 호가·체결 대응형 레버리지 단타 (PAPER)

## 결론

핵심은 **가격을 예언하지 않고 지금 들어오는 실제 공격적 매수·매도와
반대편 호가 잔량을 확인한 후, 받아줄 유동성이 있는 크기로 대응하는 것**이다.

기존 `bybit_forward.py`는 현물 BTC/ETH/SOL의 최우선 호가를 증거로 수집한다.
이 프로토타입은 이를 변경하지 않고 **Bybit USDT 무기한 선물 공공
WebSocket**의 `orderbook.1` 및 `publicTrade`를 별도로 구독한다.

`one_trading/ai_native/scalp_flow.py`는 네트워크가 실제로 연결되면
실시간 데이터를 읽고 **모의 롱·숏 진입/청산**까지 자동 수행한다.
계정 인증, 실제 주문, 입출금, 모델 호출, 백그라운드 서버는 존재하지 않는다.
기본값으로는 네트워크에 접속하지 않는다.

## 즉시 실행

Python 3.12 이상을 기준으로 테스트했다.

**Windows에서 제일 빠른 방법:** 이 저장소를 다운로드해 압축 해제한 다음
`START_PAPER_WINDOWS.cmd`를 더블클릭한다. Python 3이 설치되어 있으면
필요한 WebSocket 패키지를 설치하고 5분간 공개 데이터를 관찰하며
PAPER 매매를 한 뒤 기록을 자동 검증한다. 결과는 압축 해제 폴더의
`paper_runs`에 **새 폴더**로 남는다. 최초 실행에서 Windows의 `py` 또는
`python` 명령을 찾지 못하면 Python 설치가 필요하다.

```sh
python -m unittest discover -s tests -p test_scalp_flow.py -v
python -m pip install websockets==16.0
python -m one_trading.ai_native.scalp_flow live \
  --enable-public-network --symbol SOLUSDT --capital-usdt 10000 \
  --duration-seconds 300 --max-inputs 100000 \
  --output-dir /tmp/one_scalp_paper_001
python -m one_trading.ai_native.scalp_flow verify \
  --events /tmp/one_scalp_paper_001/events.jsonl
```

Windows PowerShell에서도 동일한 `python -m ...` 명령을 사용한다.
`--output-dir`만 `C:\one_paper\run_001` 등 **이미 존재하는 상위 폴더
아래의 새 경로**로 바꾼다. 결과 폴더는 자동 생성되며 기존 결과를 덮어쓰지 않는다.
거래 흐름이 충분하지 않으면 **0회 거래**가 정상 결과다.

비공개에 보관할 JSONL은 입력 원문, 수신 시각, 입력 해시,
관측치, 주문 대기, 모의체결, 비용, 손익, 종료 이유를 해시 체인으로 남긴다.
`verify`는 입력을 처음부터 재생성하고 판단·모의체결 결과를 다시 계산해
동일한지 확인한다. **별도 구현으로 작성된 독립 감사기는 아직 아니다.**

## 어떤 조건에서 움직이는가

| 항목 | 기본값 | 이유 |
|---|---:|---|
| 초기 가상자본 | 10,000 USDT | 실제 보유 현금과 무관한 실험 단위 |
| 최대 레버리지 | 3배 | 손실 확대 상한을 정한 초기 검증 단계 |
| 투입 증거금 상한 | 자산의 10% | 전체 자산을 한 방향에 베팅하지 않음 |
| 거래당 추정 손실 예산 | 자산의 0.5% | 손절폭+양방향 수수료·슬리피지 반영 |
| 일 손실 중단 | 일 시작 자산의 2% | 더 이상 신규 진입하지 않음 |
| 최고점 대비 낙폭 중단 | 8% | 신규 진입 차단 및 열린 포지션 청산 시도 |
| 최우선 호가 참여 비율 | 최대 3% | 예측한 수익을 호가가 못 받아주는 상황 제어 |
| 공격적 체결 확인 | 15초·15건·10만 USDT 이상 | 유의미한 체결 유입만 후보로 사용 |
| 매수·매도 체결 불균형 | 절댓값 0.25 이상 | 매수/매도 주도권의 부호 확인 |
| 최우선 호가 잔량 불균형 | 절댓값 0.12 이상 | 같은 방향의 호가 지지 여부 확인 |
| 실제 미드 가격 반응 | 방향별 0.6bp 이상 | 체결만 있고 가격이 받쳐주지 않으면 제외 |
| 진입 최대 스프레드 | 5bp | 비용이 큰 호가 제외 |
| 모의 주문 지연 | 최소 250ms | 신호를 만든 동일 호가에서는 체결 금지 |
| 손절 / 목표 | 35bp / 80bp | 실시간 반응 후 다음 호가에서 모의체결 |
| 최대 보유 | 90초 | 단타 가설이 틀어지면 장기 보유로 전환하지 않음 |

최우선 호가의 크기는 **실제 체결 보장량이 아니다**. 호가는 취소될 수 있고,
`publicTrade`의 공격적 체결은 과거에 체결된 유입이다. 둘을 합쳐도
미래 수요를 보장하지 않는다. 이 프로토타입은 분석의 경계를 숫자로 남긴다.

### 실행상 중요한 차이

- **같은 신호 패킷으로 체결하지 않는다.** 의사결정 최소 250ms 이후 들어온
  *새 책(book) 수신*이 있어야 모의 주문을 실행한다.
- **수요가 부족하면 수량을 줄인다.** 주문 명목가치는 증거금·손실 예산·
  실제 해당 방향 최우선 호가 잔량의 3% 중 최소값을 사용한다.
- **출구도 유동성을 제한한다.** 목표/손절 도달 직후 자동 수익/손실 확정으로
  처리하지 않는다. 후속 호가에서 청산량이 부족하면 일부만 청산하고
  잔여 포지션을 노출된 상태로 둔다.
- **거래 비용은 수익보다 먼저 계산한다.** 기본 가정은 양쪽 모두 taker
  수수료 5.5bp, 슬리피지 3bp이다. 펀딩비, 강제청산, 호가 뒤쪽 잔량,
  다중 호가, 체결수량 단위와 거래소 주문 거절은 아직 시뮬레이션에 없다.
- **연결이 끊기면 현재 수급 판단을 버린다.** 이전 테이프로 신규 진입하지
  않으며, 열려 있는 모의 포지션의 청산 의도는 유지한다.
- **결과를 만들기 위해 거래하지 않는다.** 모든 조건이 맞지 않으면 CASH.

## 시험의 합격 기준 및 다음 버전

첫 단계의 합격은 **실제 공공 피드 수신 → 재현 가능한 입력 로그 →
지연된 PAPER 주문 → 호가잔량·비용을 반영한 청산 → 원문 재생 검증 PASS**이다.
현 단계의 단위시험 17개는 합성 자료/모의 소켓을 사용한다.
이는 **실제 시장에서의 수익성 검증 결과가 아니다**.

실제 단타 우위 여부는 이후 여러 시장 상태에서 누적된 **미래 데이터**로
판정한다. 최소 보고 지표: 체결 수, 무거래 시간, 신호 후 가격 변화,
진입/청산 호가 깊이, 순손익, 최대낙폭, 비용/총이익 비율,
청산 실패·지연 시간, 1,000만/2,000만원 환산 일·월 순현금흐름.

탈락시키는 접근:

1. 엘리엇·하모닉 등 차트 형상만으로 진입 확정.
2. 뉴스·매크로의 예상 해석만으로 롱/숏 확정.
3. 거래대금이 없는데 이론상 수익배수만 크게 잡는 소형주 추격.
4. 같은 시점 호가에 가상 주문을 체결시키는 백테스트.
5. 높은 레버리지와 큰 주문을 처음부터 동시에 허용하는 방식.

코드의 기본 임계치는 **출발점이지 검증된 알파가 아니다**. 계좌 주문 API,
수익 보장, 매매 추천 기능으로 오해해서는 안 된다. 실제로 돈을 벌려면
수익성·체결성 검증 이후에만 주문 라우터·실계좌 킬스위치를 추가한다.
